# JobRadar application assistant

JobRadar can make a German application draft from four multiple-choice answers. Drafts from the built-in template work without an account. The optional Worker uses the OpenAI Responses API for AI-generated drafts.

## Deploy from GitHub

Use the repository’s [Actions secrets settings](https://github.com/behrens-fangpunkt/jobradar-update/settings/secrets/actions). Create these repository secrets through **New repository secret**.

| Secret | Value |
| --- | --- |
| `OPENAI_API_KEY` | An [OpenAI project API key](https://platform.openai.com/api-keys) with Responses API access and available API billing |
| `ASSISTANT_CODE` | A separate random access code of 24–128 characters using letters, numbers, underscores, or hyphens |
| `CLOUDFLARE_API_TOKEN` | A Cloudflare API token scoped to the account and authorized to deploy Workers |
| `CLOUDFLARE_ACCOUNT_ID` | The Cloudflare account ID for the Worker |

Activate the account’s `workers.dev` subdomain in the Cloudflare Workers dashboard. The [Cloudflare GitHub Actions guide](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/) explains how to create the deployment token and find the account ID.

Run [Deploy JobRadar assistant](https://github.com/behrens-fangpunkt/jobradar-update/actions/workflows/deploy-assistant.yml) on `main`. The workflow deploys the Worker and makes one OpenAI request with fictional application details. JobRadar v14 has the default service URL built in on iOS and Android.

## Approve a phone

1. In JobRadar v14, open **Assistent** on a business card and answer the four questions. On a new phone, use **Freischaltcode teilen** to send its activation code to the repository owner.
2. In GitHub, run **Deploy JobRadar assistant** and paste the activation code into **Phone activation codes**. To approve multiple phones, enter all approved codes separated by commas. To retain current approvals during a redeploy, leave the field empty. To revoke all phone approvals, enter `none`.
3. Once the run succeeds, reopen the assistant or press **Freigabe prüfen**. **KI-Entwurf erstellen** is available on that phone. Its approval persists across app updates.

The shared `ASSISTANT_CODE` still authorizes the deployment test and existing devices configured in v13. The activation code shown by v14 identifies a phone without exposing the private credential generated on it. To rotate the OpenAI API key, replace the GitHub secret and run the workflow again.

The Worker accepts the company name, industry and four answer codes. JobRadar adds the greeting and the applicant name locally. **In Mail öffnen** opens an editable draft in the phone’s mail app. The Worker limits draft requests and sets `store: false` on OpenAI requests.

## Enable Bewerbungen in JobRadar v17

The **Bewerbungen** view can connect one mailbox at a time. It shows applications sent through JobRadar and synchronizes only their conversations when it opens or when the user selects **Aktualisieren**. The email feature is disabled until the deployment has a database, encryption key and at least one configured mail provider. The existing assistant deployment works with those settings omitted.

1. Create a Cloudflare D1 database named `jobradar-mail`. Add its ID as the repository Actions **variable** `MAIL_DATABASE_ID`. The deploy workflow applies the database migration. Give the Cloudflare deployment token D1 write access if its existing policy lacks it.
2. Create a repository Actions **secret** named `MAIL_TOKEN_KEY`. Use an independent base64 key generated by `openssl rand -base64 32`. Keep this key across deployments to preserve existing mailbox connections.
3. For Outlook and Hotmail, register a Microsoft Entra application supporting personal Microsoft accounts and work or school accounts. Add a **Web** redirect URI of `https://jobradar-assistant.billowing-shape-d74b.workers.dev/mail/callback/outlook`. Add delegated Microsoft Graph permissions `User.Read`, `Mail.ReadWrite` and `Mail.Send`. Put the client ID and secret in `MICROSOFT_CLIENT_ID` and `MICROSOFT_CLIENT_SECRET`. [Microsoft OAuth configuration](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow)
4. For Gmail, enable the Gmail API, configure the consent screen and register a **Web application** OAuth client. Add `https://jobradar-assistant.billowing-shape-d74b.workers.dev/mail/callback/gmail` as its authorized redirect URI. Use the `gmail.readonly` and `gmail.send` scopes. Save its credentials as `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. For a private pilot, add the tester’s Google account to the consent screen. Before a public Gmail launch, follow Google’s restricted-scope verification requirements. [Google OAuth configuration](https://developers.google.com/identity/protocols/oauth2/web-server) · [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes)
5. Run **Deploy JobRadar assistant**. In JobRadar v17, open **Bewerbungen**, pick the provider, sign in, then copy the confirmation code from the browser back into JobRadar. This is the one-time handoff from the account’s browser sign-in to the installed app.

To test, send a reviewed message to an inbox you control. The application appears in **Bewerbungen** when the mailbox confirms sending. Reply from that inbox, then reopen or refresh the conversation in JobRadar. The mailbox supplies message contents on request. JobRadar stores encrypted mailbox credentials and application metadata, and keeps message bodies and attachments out of the AI service.
